2A. Fundamentos · Tópico 1

Estrutura e execução

Um script é um arquivo de texto com comandos executados em ordem. Entender como o shell encontra e roda o arquivo evita a maioria dos erros iniciais.

O que estudar

  • Shebang: #!/usr/bin/env bash e por que é melhor que #!/bin/sh para scripts Bash
  • Permissão de execução e as formas de rodar: ./script.sh, bash script.sh, source script.sh (e a diferença)
  • Bash vs sh vs zsh: o que é POSIX
  • Comentários e cabeçalho com descrição e uso
  • Debug: bash -x e set -x
  • Onde guardar: ~/bin, /usr/local/bin e o $PATH
#!/usr/bin/env bash # saudacao.sh: exibe usuário, host e data # uso: ./saudacao.sh echo "Olá, $(whoami) em $(hostname). Hoje: $(date +%F)" chmod +x saudacao.sh && ./saudacao.sh bash -x saudacao.sh # mostra cada linha executada

2A. Fundamentos · Tópico 2

Variáveis e expansões

O Bash faz várias expansões antes de executar um comando. Saber a ordem delas explica comportamentos estranhos.

O que estudar

  • Atribuição: NOME="valor" sem espaços em volta do =
  • Aspas: duplas expandem variáveis, simples não, e por que sempre usar "$VAR"
  • Substituição de comando: $(comando)
  • Aritmética: $(( a + b ))
  • Expansão de parâmetros: ${VAR:-padrão}, ${VAR:?erro}, ${#VAR}, ${VAR%.txt}, ${VAR/a/b}
  • Variáveis de ambiente: export, env, .env
  • Variáveis especiais: $0, $1..$9, $@, $#, $$, $?
  • Entrada do usuário: read -rp
AMBIENTE="${1:-dev}" # padrão se vazio ARQ="relatorio.txt" echo "${ARQ%.txt}.csv" # relatorio.csv TOTAL=$(( 10 * 3 )) DATA=$(date +%Y%m%d) echo "Script $0 com $# argumentos: $@" read -rp "Confirmar deploy em $AMBIENTE? [s/N] " OK

Exit codes e operadores

Todo comando retorna um código: 0 é sucesso, de 1 a 255 é erro. Pipelines de CI, cron e systemd decidem tudo com base nisso.

O que estudar

  • $? e o código do último comando
  • && e || para encadear por sucesso ou falha
  • ; e agrupamento com { } e ( )
  • exit N e convenções (1 erro geral, 2 uso incorreto, 127 comando não encontrado)
  • true, false e o comando :
ls /nao-existe ; echo $? # 2 mkdir -p /tmp/app && echo "criado" ping -c1 -W1 db || echo "banco fora do ar" command -v docker >/dev/null || { echo "instale o docker"; exit 1; }
O padrão command -v ferramenta || exit 1 no início do script verifica dependências antes de começar.

Testes e condicionais

O que estudar

  • [[ ]] vs [ ]: por que preferir [[ ]] no Bash
  • Testes de arquivo: -f, -d, -e, -r, -w, -x, -s
  • Strings: ==, !=, -z (vazia), -n (não vazia), =~ (regex)
  • Números: -eq, -ne, -gt, -lt, -ge, -le ou (( ))
  • if, elif, else e case com padrões
  • Lógica: &&, || e ! dentro dos testes
if [[ ! -f "$CONF" ]]; then echo "config ausente" >&2; exit 1 elif [[ "$AMBIENTE" =~ ^(dev|prod)$ ]]; then echo "ok: $AMBIENTE" fi (( USO > 80 )) && echo "disco acima de 80%" case "$1" in start|up) iniciar ;; stop) parar ;; *) echo "uso: $0 {start|stop}"; exit 2 ;; esac

Laços e arrays

Funções e argumentos

O que estudar

  • Argumentos de função: $1, $@ dentro da função

2C. Texto e dados · Tópico 8

grep, sed, awk e regex

O trio clássico para analisar logs e editar configurações em massa, base das tarefas de text processing do roadmap Linux.

O que estudar

  • Expressões regulares: ., *, +, ?, ^, $, [ ], grupos, básicas vs estendidas (-E)
  • grep: -i, -v, -c, -r, -o, -E, -A e -B para contexto
  • sed: substituição s///g, -i para editar no lugar, apagar linhas
  • awk: campos $1 $NF, -F separador, filtros, somas e médias
  • Combinando: sort, uniq -c, sort -rn, head
# top 10 IPs no log do Nginx awk '{print $1}' access.log | sort | uniq -c | sort -rn | head # requisições com erro 5xx grep -E '" 5[0-9]{2} ' access.log | wc -l # média do tempo de resposta (último campo) awk '{s+=$NF} END {print s/NR}' access.log sed -i 's/^PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config

APIs: curl e jq

AWS, GitHub, Cloudflare e quase toda ferramenta moderna têm API REST em JSON. curl faz a chamada, jq extrai os dados.

O que estudar

  • curl: -s, -f, -X, -H, -d, -o, -w "%{http_code}", --retry
  • Autenticação: header Authorization: Bearer com token em variável
  • JSON: objetos, arrays e tipos (MDN)
  • jq: .campo, .[], select(), map(), -r para texto puro
  • Health checks e retentativas
curl -s https://api.github.com/repos/hashicorp/terraform \ | jq '{estrelas: .stargazers_count, linguagem: .language}' curl -s -H "Authorization: Bearer $CF_TOKEN" \ "https://api.cloudflare.com/client/v4/zones" | jq -r '.result[].name' STATUS=$(curl -s -o /dev/null -w "%{http_code}" https://meu-app.com/health) [[ "$STATUS" == "200" ]] || echo "app com problema: $STATUS"

2D. Robustez · Tópico 11

Tratamento de erros

Por padrão, o Bash segue em frente depois de um erro. Em automação, o script tem que parar, limpar o que fez e avisar.

O que estudar

  • Modo estrito: set -euo pipefail e o que cada flag faz
  • Limitações do set -e (dentro de if, com || e em subshells)
  • trap: EXIT para limpeza, ERR para relatar a linha do erro, INT e TERM
  • Arquivos temporários seguros com mktemp
  • Mensagens de erro no stderr e códigos de saída significativos
  • Retentativas com backoff
#!/usr/bin/env bash set -euo pipefail TMP=$(mktemp -d) trap 'rm -rf "$TMP"' EXIT trap 'echo "erro na linha $LINENO" >&2' ERR retry() { local n=0; until "$@"; do (( ++n >= 5 )) && return 1; sleep $((n*2)); done; } retry curl -sf https://api.exemplo.com/health

Idempotência, logs e lint

O que estudar

  • Idempotência: rodar duas vezes tem o mesmo resultado (mkdir -p, verificar antes de criar)
  • Logs: data e nível em cada linha, logger para o syslog
  • ShellCheck: análise estática que encontra bugs comuns
  • shfmt: formatação padronizada
  • Testes de scripts com bats
  • Quando trocar de linguagem: scripts maiores que ~200 linhas ou com lógica complexa vão melhor em Python ou Go
id deploy &>/dev/null || useradd -m deploy grep -qxF 'vm.swappiness=10' /etc/sysctl.conf || echo 'vm.swappiness=10' >> /etc/sysctl.conf log() { echo "$(date '+%F %T') [$1] ${*:2}" | tee -a /var/log/app-deploy.log; } log INFO "deploy iniciado" shellcheck *.sh && shfmt -d .
Idempotência é o coração do Terraform (módulo 6) e de qualquer ferramenta de configuração.

DevSecOps

Scripts seguros

O que estudar e aplicar

  1. Injeção de comandos: nunca use eval com entrada externa; sempre aspas em variáveis
  2. Validação de entrada: whitelist com regex antes de usar
  3. Segredos: variáveis de ambiente ou cofre (AWS Secrets Manager, Vault), nunca no código nem em argumentos visíveis no ps
  4. Permissões: 700 para scripts sensíveis, 600 para .env, umask 077
  5. Temporários: mktemp, nunca nomes previsíveis em /tmp
  6. rm protegido: "${DIR:?}" aborta se a variável estiver vazia
  7. Downloads: verificar checksum antes de executar (evite curl | bash sem revisar)
  8. ShellCheck no CI (módulo 5)
[[ "$AMB" =~ ^(dev|staging|prod)$ ]] || { echo "ambiente inválido"; exit 2; } rm -rf "${BUILD_DIR:?variável vazia}/" sha256sum -c ferramenta.sha256
