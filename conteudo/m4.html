Módulo 4: a nuvem AWS

Segue o roadmap de AWS do roadmap.sh: fundamentos, IAM, VPC, EC2, S3, RDS, balanceamento, CloudWatch e custos. É onde a aplicação do módulo 3 vai rodar.

  1. Crie a conta e configure um alerta de orçamento antes de tudo
  2. Abra os tópicos em ordem
  3. Faça cada exercício pelo console e depois repita pela AWS CLI
  4. Desligue recursos ao final de cada sessão
Use sempre a mesma região nos estudos (por exemplo us-east-1) para não perder recursos esquecidos em outra.

4A. Base e IAM · Tópico 2

IAM: identidades

O que estudar

  • Usuário root: só para tarefas de conta, protegido com MFA
  • Usuários e grupos IAM: permissões por grupo, não por usuário
  • Roles: identidades temporárias assumidas por serviços, pessoas ou sistemas externos
  • Instance profile: role da EC2
  • IAM Identity Center (SSO): o jeito moderno de dar acesso a pessoas
  • Credenciais: senha, access keys de longa duração vs credenciais temporárias via STS
  • Federação e OIDC (usado pelo GitHub Actions no módulo 5)
  • AWS Organizations: várias contas (dev, prod) e SCPs (conceito)
aws iam create-group --group-name devs aws iam attach-group-policy --group-name devs \ --policy-arn arn:aws:iam::aws:policy/ReadOnlyAccess aws sts assume-role --role-arn arn:aws:iam::123:role/admin \ --role-session-name ramon

4A. Base e IAM · Tópico 3

IAM: policies e acesso

O que estudar

  • Estrutura: Version, Statement, Effect, Action, Resource, Condition
  • Tipos: gerenciadas pela AWS, gerenciadas pelo cliente, inline
  • Identity-based vs resource-based (bucket policy, trust policy de role)
  • Avaliação: negado por padrão, Allow explícito, Deny explícito sempre vence
  • Conditions: aws:SourceIp, aws:MultiFactorAuthPresent, tags
  • Ferramentas: Policy Simulator, IAM Access Analyzer, last accessed
{ "Version": "2012-10-17", "Statement": [{ "Effect": "Allow", "Action": ["s3:GetObject", "s3:PutObject"], "Resource": "arn:aws:s3:::app-uploads/*", "Condition": {"Bool": {"aws:SecureTransport": "true"}} }] }
Comece pelo mínimo e libere conforme a necessidade. "Action": "*" com "Resource": "*" é praticamente admin.

4B. Rede (VPC) · Tópico 4

VPC e subnets

A VPC aplica na nuvem tudo o que você viu de IP e sub-redes no módulo 1.

O que estudar

  • VPC: rede isolada por região, bloco CIDR (/16 é comum)
  • Subnets: cada uma numa AZ; públicas, privadas e isoladas
  • Endereços reservados: a AWS reserva 5 IPs por subnet
  • Desenho multi-AZ: pelo menos duas AZs para alta disponibilidade
  • VPC padrão vs VPC customizada
  • IPs: privado, público automático e Elastic IP
VPC 10.0.0.0/16 ├─ pública-a 10.0.1.0/24 web, ALB, NAT ├─ pública-b 10.0.2.0/24 ├─ privada-a 10.0.11.0/24 aplicação ├─ privada-b 10.0.12.0/24 ├─ dados-a 10.0.21.0/24 RDS (sem saída) └─ dados-b 10.0.22.0/24

4B. Rede (VPC) · Tópico 5

Gateways, rotas e conexões

O que estudar

  • Route tables: uma por tipo de subnet, rota local e rota padrão
  • Internet Gateway: torna a subnet pública
  • NAT Gateway: saída para a internet a partir da privada (custo por hora e por GB)
  • VPC Endpoints: acessar S3, ECR e outros sem passar pela internet
  • VPC Peering e Transit Gateway: conectar VPCs
  • Site-to-Site VPN e Direct Connect (conceito)
  • VPC Flow Logs para ver o tráfego
pública: 10.0.0.0/16 → local | 0.0.0.0/0 → igw-xxx privada: 10.0.0.0/16 → local | 0.0.0.0/0 → nat-xxx dados: 10.0.0.0/16 → local (sem internet) S3: prefix-list → vpce-xxx (gateway endpoint, grátis)
Em estudos, use NAT por pouco tempo ou VPC endpoints: o NAT Gateway é um dos custos que mais surpreendem iniciantes.

4B. Rede (VPC) · Tópico 6

Security Groups, NACLs e DNS

O que estudar

  • Security Group: stateful, por interface, só regras Allow, pode referenciar outro SG
  • NACL: stateless, por subnet, Allow e Deny, regras numeradas, portas efêmeras
  • Desenho em camadas: ALB aceita 443 da internet, app aceita só do ALB, banco só da app
  • Route 53: hosted zones públicas e privadas, registros alias, health checks, roteamento
  • Cloudflare na frente da AWS: DNS com proxy, WAF e cache, restringindo a origem aos IPs da Cloudflare
sg-alb: in 443 de 0.0.0.0/0 sg-app: in 8000 de sg-alb sg-db: in 5432 de sg-app aws ec2 describe-security-groups --group-ids sg-xxx
Nunca abra 22 ou 5432 para 0.0.0.0/0. Para acesso administrativo, use Session Manager.

EC2, EBS e Auto Scaling

O que estudar

  • Instâncias: AMI, famílias (t, m, c, r, g) e tamanhos, arquiteturas x86 e Graviton (arm)

  • Metadados: IMDSv2

S3 e CloudFront

O que estudar

  • Conceitos: bucket, objeto, chave, prefixo, nomes únicos globais
  • Classes de armazenamento: Standard, IA, Glacier, Intelligent-Tiering

CloudWatch métricas e alarmes

O que estudar

  • Métricas: namespaces, dimensões, períodos, estatísticas (Average, p99)
  • Métricas padrão vs customizadas (memória e disco precisam do agent)

DevSecOps

Segurança na AWS

O que estudar e aplicar

  1. Conta: MFA no root e em todos, sem access keys no root
  2. Menor privilégio e roles em vez de chaves de longa duração
  3. Rede em camadas: só o load balancer exposto, banco isolado
  4. Criptografia: KMS em EBS, RDS e S3; TLS em trânsito com ACM
  5. Segredos: Secrets Manager ou Parameter Store
  6. Detecção: GuardDuty, Security Hub, IAM Access Analyzer, Inspector
  7. Borda: AWS WAF e Shield, ou Cloudflare WAF e proteção DDoS
  8. Auditoria: CloudTrail em todas as regiões, Config
  9. Backups testados e snapshots criptografados
aws guardduty create-detector --enable aws securityhub enable-security-hub aws accessanalyzer create-analyzer --analyzer-name conta --type ACCOUNT
