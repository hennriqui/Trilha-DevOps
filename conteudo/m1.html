Quase toda infraestrutura roda em Linux, conversa por rede e é versionada com Git. Este módulo cobre o essencial dos roadmaps de Linux e Network Engineer do roadmap.sh, com HTTP pela MDN e DNS e segurança de borda pela Cloudflare.

  3. Pratique tudo numa VM Ubuntu, no WSL ou numa instância na nuvem

1A. Linux · Tópico 1

Terminal e navegação

O shell (Bash) interpreta seus comandos. Como DevOps você vai administrar servidores sem interface gráfica, então precisa se mover pelo sistema e achar ajuda sozinho.

O que estudar

  • Hierarquia de diretórios (FHS): / raiz, /etc configurações, /var/log logs, /home usuários, /usr/bin programas, /tmp temporários, /proc e /sys informações do kernel
  • Caminhos absolutos e relativos: /etc/nginx vs ../config, os atalhos ~ . e ..
  • Navegação e manipulação: pwd, ls -lah, cd, mkdir -p, touch, cp -r, mv, rm -r, tree
  • Buscar ajuda: man, comando --help, tldr, apropos, type e which
  • Produtividade: Tab para completar, Ctrl+R para buscar no histórico, history, alias, variáveis como $PATH e $HOME, o arquivo ~/.bashrc
man ls # manual completo ls -lah /var/log # detalhes, ocultos, tamanhos legíveis cd ~ ; cd - ; cd .. echo $PATH alias ll='ls -lah' # adicione ao ~/.bashrc
Exercício: sem interface gráfica, encontre onde fica a configuração do SSH e quantos arquivos existem em /etc.

1A. Linux · Tópico 2

Arquivos e texto

No Linux, configurações, logs e saídas de comandos são texto. Ler, filtrar, editar e compactar texto é uma tarefa diária.

O que estudar

  • Ler arquivos: cat, less, head, tail e tail -f para logs ao vivo
  • Editores: vim (modos normal, inserção e comando) e nano
  • Processamento de texto: grep, sort, uniq, cut, tr, wc, diff, tee
  • Streams: stdin, stdout e stderr, pipes |, redirecionamentos >, >>, 2>&1
  • Busca: find por nome, tamanho e data; locate
  • Links: hard link vs link simbólico (ln -s)
  • Compactação: tar, gzip, zip
tail -f /var/log/syslog grep -rin "error" /var/log/nginx/ find /var/log -name "*.log" -mtime -1 -size +10M cut -d: -f1 /etc/passwd | sort tar -czf backup.tar.gz /etc/nginx ln -s /opt/app/v2 /opt/app/atual
Vim mínimo: i insere, Esc volta ao modo normal, /texto busca, dd apaga linha, :wq salva e sai, :q! sai sem salvar.

1A. Linux · Tópico 3

Usuários e permissões

Linux é multiusuário: cada arquivo e processo pertence a alguém. Errar permissões é uma das causas mais comuns de falhas e de brechas de segurança.

O que estudar

  • Usuários e grupos: /etc/passwd, /etc/shadow, /etc/group, useradd, usermod -aG, passwd, id, groups
  • sudo: o arquivo sudoers, visudo e o grupo sudo ou wheel
  • Permissões rwx: dono, grupo e outros; notação octal (755, 644, 600) e simbólica (u+x, g-w)
  • chmod, chown e chgrp, inclusive -R
  • umask: permissão padrão de arquivos novos
  • Permissões especiais: setuid, setgid e sticky bit (por que /tmp tem o t)
  • ACLs: getfacl e setfacl para casos finos
sudo useradd -m -s /bin/bash deploy sudo usermod -aG sudo deploy ls -l app.conf # -rw-r----- 1 app app chmod 640 app.conf # 6=rw 4=r 0=nada chmod u+x script.sh sudo chown -R app:app /srv/app umask # geralmente 0022
Menor privilégio: nunca chmod 777. Chaves e .env com 600, scripts com 750, e serviços com usuário próprio.

1A. Linux · Tópico 4

Processos e serviços

Todo programa em execução é um processo com PID, dono e consumo de recursos. Serviços de longa duração (Nginx, Docker, banco) são gerenciados pelo systemd.

O que estudar

  • Listar e monitorar: ps aux, pstree, top, htop, uptime e load average
  • Sinais: SIGTERM (15) vs SIGKILL (9), SIGHUP para recarregar; kill, pkill, killall
  • Primeiro e segundo plano: &, jobs, fg, bg, nohup, Ctrl+Z
  • Prioridade: nice e renice
  • systemd: units, systemctl start, stop, restart, reload, enable, status
  • Criar seu próprio serviço com um arquivo .service
  • Logs: journalctl -u, -f, --since
  • Recursos: free -h, vmstat, iostat, lsof
# /etc/systemd/system/minha-api.service [Unit] Description=Minha API After=network.target [Service] User=app ExecStart=/opt/app/server Restart=on-failure [Install] WantedBy=multi-user.target sudo systemctl daemon-reload sudo systemctl enable --now minha-api journalctl -u minha-api -f

1A. Linux · Tópico 5

Pacotes, discos e boot

Instalar software, cuidar do armazenamento e entender como o sistema liga fecha a base de administração Linux.

O que estudar

  • Gerenciadores de pacotes: apt (Debian, Ubuntu), dnf (RHEL, Fedora), repositórios, chaves GPG, snap
  • Discos: lsblk, fdisk, df -h, du -sh, partições
  • Sistemas de arquivos: ext4, xfs, mkfs, mount, /etc/fstab, inodes
  • Swap e LVM: o que são e quando usar
  • Processo de boot: BIOS ou UEFI, GRUB, kernel, systemd e targets
  • Troubleshooting: dmesg, journalctl -b -p err, disco cheio, falta de memória (OOM killer)
sudo apt update && sudo apt upgrade -y apt search nginx ; apt show nginx lsblk ; df -h ; du -sh /var/* | sort -h sudo mkfs.ext4 /dev/xvdf sudo mount /dev/xvdf /dados dmesg | tail ; journalctl -b -p err
Disco cheio derruba bancos e aplicações. Verifique df -h e df -i (inodes) sempre que algo parar sem motivo aparente.

1B. Redes · Tópico 6

IP, sub-redes e roteamento

Antes de qualquer nuvem, entenda como os pacotes encontram o caminho. É isso que você vai desenhar ao criar uma VPC no módulo 4.

O que estudar

  • Modelos OSI (7 camadas) e TCP/IP (4 camadas): o que acontece em cada uma
  • MAC, ARP e switches (camada 2) vs IP e roteadores (camada 3)
  • IPv4 e IPv6: formato, IP público vs privado (10/8, 172.16/12, 192.168/16)
  • CIDR e subnetting: calcular rede, broadcast e hosts de um /24, /26, /16
  • Gateway e tabela de rotas, rota padrão 0.0.0.0/0
  • NAT: como redes privadas saem para a internet
  • DHCP: distribuição automática de IPs
  • VLANs e topologias (conceito)
ip a # interfaces e IPs ip route # rotas e gateway ip neigh # tabela ARP ping -c 4 8.8.8.8 traceroute google.com ipcalc 10.0.1.0/26 # 64 endereços, 62 hosts
Treine subnetting até fazer de cabeça: /24=256, /25=128, /26=64, /27=32, /28=16 endereços.

1B. Redes · Tópico 7

DNS

O DNS traduz nomes em endereços. Quase todo deploy envolve criar ou mudar registros, e muitos incidentes começam aqui.

O que estudar

  • Resolução: resolver recursivo, servidores raiz, TLD (.com, .br) e servidor autoritativo
  • Registros: A, AAAA, CNAME, MX, TXT, NS, SOA, CAA
  • TTL e cache: por que mudanças demoram a propagar
  • Resolução local: /etc/hosts e /etc/resolv.conf
  • Registrar vs provedor de DNS: onde se compra o domínio e onde ficam os registros
  • Cloudflare DNS: registros com proxy (nuvem laranja) escondem o IP de origem; DNS only não
  • DNSSEC e registros de e-mail SPF, DKIM e DMARC
dig exemplo.com +short dig exemplo.com MX dig +trace exemplo.com # caminho completo dig @1.1.1.1 exemplo.com # perguntar a um resolver nslookup exemplo.com
Cuidado com subdomain takeover: CNAME apontando para um serviço que você já desligou pode ser assumido por terceiros.

1B. Redes · Tópico 8

HTTP, HTTPS e TLS

HTTP é a língua da web e das APIs. Você vai depurar status codes, headers e certificados o tempo todo.

O que estudar

  • Requisição e resposta: método, URL, headers, corpo (MDN)
  • Métodos: GET, POST, PUT, PATCH, DELETE e idempotência
  • Status codes: 2xx, 3xx (301, 302, 304), 4xx (400, 401, 403, 404, 429), 5xx (500, 502, 503, 504)
  • Headers importantes: Host, Content-Type, Authorization, Cache-Control, Set-Cookie
  • Cookies, cache e CORS
  • TLS: handshake, certificados, cadeia de confiança, Let's Encrypt
  • Modos SSL da Cloudflare: Flexible, Full e Full (strict), e por que usar strict
  • HTTP/1.1, HTTP/2 e HTTP/3 (diferenças principais)
curl -I https://exemplo.com # só headers curl -v https://exemplo.com # TLS e headers curl -X POST -H "Content-Type: application/json" \ -d '{"nome":"ramon"}' https://api.exemplo.com openssl s_client -connect exemplo.com:443 \ -servername exemplo.com | openssl x509 -noout -dates
502 e 504 geralmente indicam problema entre o proxy e a aplicação, não no navegador do usuário.

1B. Redes · Tópico 9

Portas, firewall e proxies

Portas identificam serviços. Firewalls decidem quem chega a elas. Proxies e load balancers distribuem e protegem o tráfego.

O que estudar

  • TCP vs UDP: three-way handshake, confiabilidade e quando usar cada um
  • Portas comuns: 22, 53, 80, 443, 3306, 5432, 6379, 8080
  • Diagnóstico: ss -tulpn, nc, telnet, tcpdump
  • Firewall no host: ufw, iptables e nftables, política padrão de negar
  • Proxy reverso: Nginx na frente da aplicação
  • Load balancer: camada 4 vs camada 7, health checks
  • CDN e WAF: como a Cloudflare faz cache na borda e bloqueia ataques e DDoS
ss -tulpn # quem escuta em qual porta nc -zv db.interno 5432 # a porta está acessível? sudo tcpdump -i any port 443 -c 20 sudo ufw default deny incoming sudo ufw allow 22/tcp && sudo ufw allow 80,443/tcp sudo ufw enable && sudo ufw status verbose
App roda mas não responde de fora? Confira: escuta em 0.0.0.0 ou só 127.0.0.1? O firewall libera? O Security Group libera?

1B. Redes · Tópico 10

SSH e acesso remoto

SSH é como você entra em servidores, copia arquivos e cria túneis seguros. Também vale conhecer as alternativas modernas ao SSH exposto.

O que estudar

  • Chaves: ssh-keygen (ed25519), ssh-copy-id, authorized_keys, ssh-agent
  • Arquivo ~/.ssh/config: apelidos, usuário, chave e porta por host
  • Cópia de arquivos: scp e rsync
  • Túneis: port forwarding -L e -R
  • Bastion ou jump host: ssh -J
  • Hardening do sshd_config e fail2ban
  • VPN: conceito e WireGuard
  • Zero Trust: Cloudflare Tunnel e AWS Session Manager, acesso sem abrir a porta 22
ssh-keygen -t ed25519 -C "ramon@notebook" ssh-copy-id deploy@203.0.113.10 rsync -avz ./site/ web:/var/www/site/ ssh -L 5432:db.interno:5432 bastion # túnel para o banco ssh -J bastion deploy@10.0.11.5 # ~/.ssh/config Host web HostName 203.0.113.10 User deploy
No /etc/ssh/sshd_config: PermitRootLogin no e PasswordAuthentication no. Reinicie com systemctl restart ssh sem fechar a sessão atual.

1C. Git · Tópico 11

Conceitos do Git

Git é um controle de versão distribuído: cada cópia tem o histórico inteiro. Em DevOps, código, infraestrutura e pipelines vivem no Git.

O que estudar

  • As três áreas: diretório de trabalho, staging (index) e repositório
  • Commit: snapshot identificado por hash SHA, com autor e mensagem
  • HEAD, branch e tag: ponteiros para commits
  • Configuração: git config global e por repositório
  • Local vs remoto (origin)
git config --global user.name "Ramon Saldana" git config --global user.email "voce@email.com" git config --global init.defaultBranch main git init meu-projeto && cd meu-projeto git status
Visualize: o Learn Git Branching mostra graficamente o que cada comando faz com os commits.

1C. Git · Tópico 12

Comandos do dia a dia

O que estudar

  • Ciclo básico: add, commit, status, diff, log
  • Desfazer com segurança: restore, revert, reset (soft, mixed, hard) e a diferença entre eles
  • Guardar trabalho temporário: stash
  • Investigar: blame, show, log --graph, reflog para recuperar commits "perdidos"
  • .gitignore e o que nunca entra no repositório
git add -p # adicionar por partes git commit -m "feat: endpoint de health" git log --oneline --graph --all git diff --staged git restore arquivo # descarta mudança local git revert a1b2c3d # desfaz criando novo commit git stash ; git stash pop git reflog # salva-vidas
Em branches compartilhadas use revert, não reset --hard: reset reescreve histórico que outras pessoas já têm.

1C. Git · Tópico 13

Branches, merge e rebase

O que estudar

  • Criar e trocar branches: switch -c, branch -d
  • Merge: fast-forward vs merge commit
  • Rebase: histórico linear, rebase -i para organizar commits
  • Conflitos: como ler os marcadores e resolver
  • cherry-pick: levar um commit específico para outra branch
  • Tags: versionamento semântico (v1.2.3)
git switch -c feature/login git switch main && git merge feature/login git rebase main # na feature git rebase -i HEAD~3 # juntar ou editar commits # conflito: edite entre <<<<<<< ======= >>>>>>> git add . && git rebase --continue git tag -a v1.0.0 -m "primeira versão"
Regra de ouro: não faça rebase de commits que já foram enviados e que outras pessoas usam.

1C. Git · Tópico 15

Fluxos e boas práticas

O que estudar

  • Trunk-based development: branches curtas e merge frequente na main (o mais usado em CI/CD)
  • GitFlow: develop, release e hotfix, e por que caiu em desuso
  • Conventional Commits: feat, fix, docs, chore, refactor
  • Commits pequenos e PRs fáceis de revisar
  • Hooks: pre-commit para lint e verificação de segredos
  • README e CHANGELOG
# .gitignore .env *.pem node_modules/ .terraform/ *.tfstate* pip install pre-commit && pre-commit install
Segredo vazou num commit? Apagar o commit não basta: revogue a chave, gere outra e só depois limpe o histórico.

Hardening e segurança da base

Segurança começa no primeiro servidor e no primeiro commit (shift-left).

O que estudar e aplicar

  1. Usuário próprio com sudo, sem uso diário do root
  2. SSH só por chave, sem root e sem senha, com fail2ban
  3. Firewall negando tudo e liberando só 22, 80 e 443
  4. Atualizações automáticas de segurança (unattended-upgrades)
  5. Serviços com usuário dedicado e permissões mínimas
  6. HTTPS com Full (strict) e IP de origem escondido atrás de proxy
  7. Segredos fora do Git com gitleaks e pre-commit
  8. main protegida e commits assinados
  9. Auditoria: last, journalctl, /var/log/auth.log
